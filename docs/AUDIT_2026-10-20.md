## Part A — Security Audit

### A.1 🔴 CRITICAL

#### C1. Hand-history IDOR — any logged-in user can read any room's hole cards
- **Where**: [web/app/api/rooms/[id]/hands/route.ts:19-23](web/app/api/rooms/%5Bid%5D/hands/route.ts#L19-L23)
- **Attack**: Any Google-logged-in user guesses or scrapes a `roomId` (25-char cuid; visible via the lobby to any logged-in user) and GETs `/api/rooms/<id>/hands`. The response includes `HandLog.data` which contains `endResult.revealedHoles` (showdown hole cards) + full action history + starting/final chips. Nothing restricts the caller to the room's memberships. A spectator can steal hole cards of an in-progress session.
- **Fix direction**: Require `session.user.id` to appear in `Room.memberships` for that `roomId`; return 403 otherwise.

#### C2. `/api/rooms` POST has no rate limit — unbounded DB growth
- **Where**: [web/app/api/rooms/route.ts:43-135](web/app/api/rooms/route.ts#L43-L135)
- **Attack**: A single logged-in user scripts N parallel POSTs; each creates a `Room` row with no throttle and no per-owner cap. Lobby broadcast gets flooded on every connect.
- **Fix direction**: Per-user rate limit (e.g. 1 room / 30s + max 5 open rooms per owner).

#### C3. Socket.IO events have no rate limiting — chat/action spam DoS
- **Where**: [server/src/index.ts:730-852](server/src/index.ts#L730-L852)
- **Attack**: `game:action`, `game:time-bank`, `chat:send`, `room:rebuy`, `room:join` have no per-user throttle (only `sticker:send` has a 3s cooldown). Chat 500-char messages at sustained rate saturate the room broadcast channel. `game:time-bank` spam eats event-loop time across many sockets.
- **Fix direction**: Per-socket + per-event token bucket (e.g. 10 msgs / 10s for chat, 5 actions / 10s for game); drop silently on exceed.

#### C4. `NEXTAUTH_SECRET` reused for both NextAuth session JWT and Socket.IO handshake JWT; `jwt.verify` doesn't pin algorithm
- **Where**: Signed at [web/app/api/socket-token/route.ts:18-22](web/app/api/socket-token/route.ts#L18-L22); verified at [server/src/auth.ts:5-25](server/src/auth.ts#L5-L25)
- **Attack**: If either side ever leaks the secret (log line, error page stack, env dump via another vuln), the attacker gets session impersonation **AND** unauthenticated socket access AND can mint tokens for arbitrary `sub` userIds. `jwt.verify(token, SECRET!)` accepts the default algorithm set — algorithm-confusion is a design risk.
- **Fix direction**: Separate `SOCKET_JWT_SECRET`; `jwt.verify(token, SECRET, { algorithms: ['HS256'] })`.

#### C5. `CORS_ORIGIN` defaults to `http://localhost:3000` with no startup check
- **Where**: [server/src/index.ts:61-73](server/src/index.ts#L61-L73)
- **Attack**: Mis-deployment with the default value causes Socket.IO handshakes from the real origin to fail silently; no one notices until users complain.
- **Fix direction**: Missing `CORS_ORIGIN` env should be a startup error, matching the `NEXTAUTH_SECRET` guard pattern already in `auth.ts`.

### A.2 🟠 HIGH

#### ~~H1~~. Google OAuth never checks `email_verified` — ⏭️ **Skipped per threat-model decision (2026-10-20)**
- **Where**: [web/lib/auth.config.ts:14-19](web/lib/auth.config.ts#L14-L19) (no `signIn` callback)
- **Original finding**: PrismaAdapter links accounts by email. An attacker controlling an unverified alias (narrow Workspace edge cases) can pre-register the victim's email and later take over when the real user signs in.
- **Decision**: Not applicable — Holdem is friends-only; every player owns a real Gmail. The stranger-attacker premise doesn't fit this threat model. Kept here for traceability only.

#### H2. Socket token has 5-min TTL with no revocation
- **Where**: [web/app/api/socket-token/route.ts:18-22](web/app/api/socket-token/route.ts#L18-L22)
- **Attack**: A stolen token (XSS, shared machine, logs) is valid for 5 min regardless of sign-out. A long-lived socket outlives the TTL entirely because handshake only verifies on connect.
- **Fix direction**: Reduce TTL to 60s; disconnect all sockets for a user on sign-out; optional JTI blocklist for revoke.

#### H3. Owner's `game:end` can be fired mid-hand → committed chips disappear
- **Where**: [server/src/index.ts:746-758](server/src/index.ts#L746-L758)
- **Attack**: `game:end` calls `endHand(roomId)` → `hands.delete(roomId)` with no check that `phase === 'ended'`. Owner can abort a losing hand before showdown; committed bets are lost in memory (never persisted via `persistHandResult`). Also enables "quick refund" collusion.
- **Fix direction**: Block `game:end` while `hasActiveHand(roomId)` (parallel to the standup block), OR force settlement on force-end.

#### H4 / H5. Socket payload lacks runtime schema validation (defense-in-depth)
- **Where**: `game:action` raise handler at [server/src/hands.ts:389-409](server/src/hands.ts#L389-L409); `room:rebuy` handler at [server/src/index.ts:705-727](server/src/index.ts#L705-L727)
- **Status**: Currently blocked (NaN / Infinity / negatives / over-stack all rejected), but TypeScript types are compile-time only. One typo in a future handler leaks state.
- **Fix direction**: Add zod schema per event at Socket entry (fixes M2 at the same time).

#### H6. `HandLog.data` jsonb unencrypted — DB breach reveals historical hole cards
- **Where**: [db/prisma/schema.prisma:152](db/prisma/schema.prisma#L152), [server/src/rooms.ts:505-521](server/src/rooms.ts#L505-L521)
- **Status**: Room-close deletes HandLogs, which contains the exposure window somewhat. Long-term consider field-level encryption.

### A.5 ✅ Explicitly checked, found OK

- Fisher-Yates shuffle via `crypto.randomInt(0, i+1)` — unbiased, correct bounds. No `Math.random` anywhere.
- `game:state` / `toPublicState` strips hole cards; `getPrivateFor` is per-socket (`socket.emit` keyed on authed `userId`). No path broadcasts another player's cards before showdown/all-in reveal.
- Deck never serialized to clients; HandLog persisted only after `phase === 'ended'` — no future-draw leak.
- Side-pot math zero-sum, deterministic, folded players counted toward layer sizes but can't win.
- Betting validation: non-finite, negative, below-call, over-stack all rejected; all-in exemption from min-raise is implemented.
- Turn enforcement: `applyAction` checks `cur.userId !== userId` → disconnected player can't act out of turn.
- `userId` always sourced from authed socket, never from payload.
- No `$queryRawUnsafe`, no raw SQL. No `dangerouslySetInnerHTML` / `innerHTML`.
- Prod `docker-compose.prod.yml`: `holdem-server` and `holdem-postgres` have no `ports:` block (unreachable from outside the docker network).
- `.gitignore` excludes `.env`, `.env.prod`, `.env.local`.
- No `NEXT_PUBLIC_*` secret leak into client bundle.
- Middleware route-protects `/lobby` and `/room`; each `/api/*` handler calls `auth()` individually.
- Owner-close rejects while `status === 'playing'`; seat is DB-unique-constrained.
- Rebuy: must be at exactly 0 chips, multiple of 500, below chip-leader cap, computed in transaction.

## Part B — Code Quality Audit

### B.1 High-impact refactors

#### R1. `broadcastAfterAction` is a God-function (14 responsibilities)
- **Where**: [server/src/index.ts:327-492](server/src/index.ts#L327-L492)
- **Smell**: action-log emit → all-in reveal → street-log → public state → private hole re-emit → DB persist → tournament-finish detection → room teardown → settlement sync → hand-log persist → status flip → drain rebuys → drain forced-standups → ended emit → room detail broadcast → reschedule timer. Every new feature forces touching this method and understanding all 14 steps.
- **Related duplication**: The hand-end tournament-finish branch (414-443) is almost verbatim repetition of `finalizeRoomState` (99-114) AND `room:close` (684-699) — **three teardown call sites to keep in sync**.
- **Direction**: Extract `handleHandEnded(roomId, hand)` and `teardownRoom(roomId, settlement?)`. `broadcastAfterAction` becomes orchestration of named steps.

#### R2. Six per-room transient Maps, cleaned in four places — one site already missing three Maps
- **Where**: [server/src/index.ts:120-218](server/src/index.ts#L120-L218)
- **Smell**: `autoActionTimers`, `lastHandLogIdByRoom`, `pendingRebuysByRoom`, `idleStreakByRoom`, `pendingForcedStandupByRoom`, `timeBankByRoom`. Must all be disposed in `finalizeRoomState`, `room:close`, tournament-finish, and `scanExpiredSessions`.
- **🐛 Already a bug**: `scanExpiredSessions` ([server/src/index.ts:878-881](server/src/index.ts#L878-L881)) only clears four — misses `pendingRebuysByRoom`, `idleStreakByRoom`, `pendingForcedStandupByRoom`. If a room expires exactly as those queues are populated, those entries leak forever.
- **Direction**: `RoomRuntimeState` record holding all per-room transient maps as fields; single `disposeRoomState(roomId)` wipes them.

#### R3. `sheetsSync.ts` has no serialization — two concurrent settlements race
- **Where**: [server/src/sheetsSync.ts:981-1016](server/src/sheetsSync.ts#L981-L1016)
- **Smell**: `syncSettlementToSheet` is fire-and-forget from 5 call sites, performs ~5 reads + ~3 writes with no cross-call lock and **no HTTP timeout**. Two rooms closing within 30s (expiry scan + owner-close) can interleave: both `getRoster` reads see length N → both assign slot N+1 to different new users → one write wins, the other becomes an orphan slot that corrupts `readPhysicalRoster` on next rebuild.
- **Direction**: Per-spreadsheet mutex (one in-flight sync; subsequent calls queue). Add `AbortSignal.timeout(10_000)` to every `fetch`. **Add the lock before any retry logic**, otherwise retries just multiply the race window.

#### R4. `maybeAdvanceIfNoAction` duplicates the entire `advancePhase` logic
- **Where**: [server/src/hands.ts:524-628](server/src/hands.ts#L524-L628)
- **Smell**: Both own copies of the `preflop→flop→turn→river→showdown` table, `dealCommunity` dispatch, reveal + history-push. The all-in runout path is the one less-exercised during manual testing — the one most likely to drift.
- **Direction**: Extract `dealNextStreet(hand)` returning the new phase; both methods loop over it.

### B.3 TypeScript / correctness tightening

#### T1. `HandLog.data` round-trips via `as unknown as HandLogData` with no runtime check
- **Where**: [server/src/rooms.ts:483, 515, 519, 546](server/src/rooms.ts#L483)
- **Impact**: Any future shared-type evolution (added field, renamed phase) silently miscasts historical rows → client renders broken history.
- **Direction**: One-time `parseHandLogData(raw: unknown): HandLogData | null` at the read sites.

#### T2. `persistHandResult` uses `updateMany` — silently succeeds with `count: 0` if Membership missing
- **Where**: [server/src/rooms.ts:459-467](server/src/rooms.ts#L459-L467)
- **Impact**: Tournament bust-mid-hand case where the player's Membership is already gone → chip delta from the hand is lost with no trace.
- **Direction**: Switch to `update` by `userId_roomId`; let P2025 throw, caught at broadcast layer.

#### T3. `applyAction` raise uses `Math.floor` but not `Number.isInteger`
- **Where**: [server/src/hands.ts:389](server/src/hands.ts#L389)
- **Status**: Not currently exploitable (100.9 → 100), but `rebuyChips` ([server/src/rooms.ts:231](server/src/rooms.ts#L231)) already enforces `Number.isInteger`. Discipline should be consistent to prevent future floating-point drift.

#### T4. Side-pot remainder goes to seat-index-lowest winner — not standard "closest-to-dealer-left"
- **Where**: [server/src/hands.ts:751-760](server/src/hands.ts#L751-L760)

#### T5. `StartHandOutcome` error branch isn't a discriminated union
- **Where**: [server/src/index.ts:494-527](server/src/index.ts#L494-L527)
- **Direction**: `{ ok: false; kind: 'needs-rebuy' | 'too-few' | 'expired' | 'exists'; error }` — compiler forces handling of new error variants.

- **Direction**: One `hands.test.ts` with ~20 cases on `buildSidePots` + `endWithShowdown` + `blindsForLevel` catches 90% of plausible regressions. No CI required.
